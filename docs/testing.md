# Проверка качества и воспроизводимость

Для запуска готового распознавателя выполните установку и скачивание модели из [README](../README.md). Для воспроизведения оценки сначала создайте `data/processed` через `pdn_lab prepare`, затем `data/hard-v2` через `scripts/prepare_hard_data.py`.

## Эталон и границы

Каждый JSONL-пример содержит `text` и список `[тип, начало, конец]`. Границы относятся к исходной строке; правая исключена. Эталон синтетических примеров задаётся при генерации, а не выводом детектора. В ручном наборе `data/context-v3` положительные фрагменты размечены автором в исходнике генератора.

Программа объединяет предсказания модели ФИО со структурированными правилами. Для итоговой оценки запускается именно объединённая система. Режим `--rules-only` предназначен для диагностики и не подтверждает выполнение задачи по всем восьми атрибутам.

## Метрики

`Precision = TP/(TP+FP)`, `Recall = TP/(TP+FN)`, `F1 = 2TP/(2TP+FP+FN)`.

Основная weighted F1 считается по B/I-меткам восьми атрибутов с весами по эталонной частоте. `O` исключена из усреднения, но токены `O` остаются в сравнении: лишнее имя в обычном тексте увеличивает FP. Дополнительно выводится F1 с `O`.

Строгая метрика целых сущностей требует совпадения типа и обеих символьных границ. Частично найденная фамилия создаёт FP для предсказанного фрагмента и FN для эталонного целого. Для проверки полного ответа используется точное совпадение всего списка сущностей в тексте. Эти показатели отвечают на разные вопросы и могут меняться в разных направлениях.

## Разделение данных

Train участвует в обновлении весов, validation — в выборе эпохи. Исходный test сохраняется при расширении данных. Полные текстовые дубликаты новых примеров исключаются между разделами и известным стресс-набором. Общие форматы и имена могут повторяться; это не независимая проверка новых предметных областей.

Манифесты содержат seed, версии исходных корпусов и SHA-256 файлов. Обучение проверяет train/validation, оценка — целостность теста и соответствие обучения манифесту. `lab_requirements_met_on_this_dataset` проверяет присутствие восьми типов, больше 50 текстов на тип, основную F1 строго выше 0,85, завершённое совместимое обучение и полный гибридный режим.

## Стресс-проверки

Основной набор содержит все 40320 перестановок восьми полей для одних базовых значений и дополнительные сложные сценарии. Показатель по всему набору следует рассматривать вместе с результатами без массовых перестановок и по категориям.

`scripts/audit_stress_cases.py` воспроизводит уточнённые 42377 примеров из исходников. Он сохраняет историю исправления шести неверно положительно размеченных карт и добавляет шесть корректных аналогов. Для работы не нужны файлы старых локальных прогонов.

Дополнительный набор из 176 текстов проверяет животное/человека с именем Лев, фамилии в названиях и прямой речи, владельцев рядом с организациями, инициалы и составные фамилии. Это поддерживаемый регрессионный набор. При доработке по найденным ошибкам он перестаёт быть независимой контрольной оценкой.

Команды для самостоятельных проверок находятся в README. `scripts/compare_*` и `scripts/verify_v2_artifacts.py` относятся к историческим локальным экспериментам: они проверяют сохранённые `reports/` и `runs/`, которые не публикуются. Их отсутствие в чистом клоне не мешает самостоятельной оценке или стресс-тесту.

## Ограничения

Валидность контрольных цифр не доказывает выдачу номера. Одинаковое слово может обозначать человека, организацию или животное; контекст иногда неоднозначен. Правила расширения составной фамилии требуют уже найденного SURNAME и подтверждающего контекста, поэтому неверный тип или полный пропуск моделью могут сохраняться.

Для утверждений о работе на реальных документах нужны отдельная ручная разметка и выборка соответствующей предметной области. Старые исследованные сценарии подтверждают отсутствие повторения известных ошибок, но не надёжность всех возможных текстов.
